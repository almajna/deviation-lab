The two compressed receipt files here were recovered from the `REALITY_FILE` sections of the original Actions job logs. They contain the consolidated `results.json` emitted in each attempt, not the complete original Actions ZIP. The original ZIPs additionally include per-case files and execution logs; durable archival of those original ZIPs remains outstanding. Do not represent this recovery as a byte-for-byte copy of the ZIPs.

From the repository root, verify the compressed bytes and recompute receipt statistics without installing LiteLLM or issuing requests:

```sh
shasum -a 256 -c artifacts/litellm-reality/SHA256SUMS
mkdir -p /tmp/deviation-litellm
gzip -dc artifacts/litellm-reality/attempt-1-results.json.gz > /tmp/deviation-litellm/attempt-1.json
gzip -dc artifacts/litellm-reality/attempt-2-results.json.gz > /tmp/deviation-litellm/attempt-2.json
python3 scripts/check_litellm_reality.py /tmp/deviation-litellm/attempt-1.json
python3 scripts/check_litellm_reality.py /tmp/deviation-litellm/attempt-2.json
```

Each checker output should report 39 cases, 936 requests and `INCONCLUSIVE_PENDING_SAFEGUARD_AND_SOURCE_REVIEW`. It checks receipt consistency and frozen comparisons; the scientific conclusion requires source and safeguards review as well. It does not rerun the router. The compressed bytes were generated by the original workflow's log-preservation step; `dependencies.txt` and `source.txt` were recovered the same way and matched across attempts.
